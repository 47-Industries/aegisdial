# AegisDial — TestFlight Build Checklist

**Prerequisite:** DEPLOY_PLAYBOOK.md steps 1–10 are done. Backend is live at https://aegisdial-api.fly.dev and you have a 10-character Apple Team ID.

This doc is what you (or whoever's at the Mac) work through.

---

## 1. Set up the Mac

```bash
# If you don't own a Mac: https://www.macincloud.com/ ~$30/mo
# Xcode Cloud is Apple's CI alternative and has a free tier.

# Install tools
xcode-select --install          # command-line tools
brew install xcodegen           # project.yml → .xcodeproj
```

Sign in to Xcode → Settings → Accounts → + → Apple ID (the one tied to the Developer Program).

---

## 2. Wire your Team ID

```bash
cd ~/aegisdial-ios
# Edit project.yml, line ~14:
#   DEVELOPMENT_TEAM: "" # fill in your Apple Developer team ID
# Change to:
#   DEVELOPMENT_TEAM: "XXXXXXXXXX"
```

Then generate the Xcode project:

```bash
xcodegen generate
open AegisDial.xcodeproj
```

---

## 3. First compile (this is the step we've never done)

The 43 Swift files have been typechecked-by-inspection but never compiled. Expect 5–20 issues on first build. Common ones:

- **Minor import missing** — `import UIKit` or `import UserNotifications` on some extension file. Xcode will autofix.
- **`#if DEBUG` in an iOS extension target** — harmless, just fix the baseURL manually.
- **Missing App Icon** — Xcode will warn. See §6 below.
- **Signing issues** — re-select the Team in the target → Signing & Capabilities.

Build **AegisDial → iPhone 15 simulator → ⌘R**. The app should launch into Onboarding.

---

## 4. Add capabilities (3 targets, one-time)

In Xcode, each target → Signing & Capabilities → + Capability:

### Main app target (`AegisDial`)
- Sign in with Apple (already in entitlements file)
- Push Notifications
- Background Modes → Remote notifications
- App Groups → `group.com.aegisdial.app` (already in entitlements)
- App Attest (already in entitlements)
- In-App Purchase

### `CallerIDExtension`
- App Groups → `group.com.aegisdial.app`

### `SMSFilterExtension`
- App Groups → `group.com.aegisdial.app`

Re-generate provisioning profiles: Xcode will auto-fix "No profiles available" by clicking **Try Again** on the error.

## 5. Register App IDs on developer.apple.com

Xcode auto-registers the main bundle ID on first build, but the two extensions sometimes don't. If you hit "no matching profiles":

https://developer.apple.com/account/resources/identifiers/list

- Add: `com.aegisdial.app.CallerID` (select capabilities: App Groups)
- Add: `com.aegisdial.app.SMSFilter` (select capabilities: App Groups)

## 6. App Icon + Launch Screen

You DON'T have an app icon yet. App Store Review will reject without a proper 1024×1024 icon.

**Quick win (MVP):** Fiverr / Dribbble designer, ~$50–200, 24–48 hr turnaround. Brief:
> "Dark icon, shield motif with a subtle phone inside. Single color accent (blue). Must work at 40×40 and at 1024×1024. Generate full iOS icon set."

Drop the resulting `.xcassets` into `~/aegisdial-ios/Assets.xcassets/AppIcon.appiconset/`.

**Launch screen** is generated by `INFOPLIST_KEY_UILaunchScreen_Generation: YES` in project.yml — Xcode renders a blank screen. If you want a logo splash, create `LaunchScreen.storyboard` and reference in project.yml.

## 7. App Store Connect setup

https://appstoreconnect.apple.com

### 7a. Create the app record
- My Apps → + → New App
- Platform: iOS
- Name: **AegisDial**
- Primary language: English (U.S.)
- Bundle ID: `com.aegisdial.app` (pick from dropdown after Xcode registered it)
- SKU: `aegisdial-ios-v1`

### 7b. After creation, grab the numeric Apple ID
- App Information → **Apple ID** (e.g. `1234567890`)
- Paste into `.env.production`: `APPLE_APP_APPLE_ID=1234567890`, then re-run `bash scripts/setup-fly-secrets.sh` + `fly deploy`.

### 7c. Privacy labels (required before upload)
- App Privacy → Get Started.
- Data types you collect:
  - **Email** (Account, Linked to User)
  - **Phone Number** (Account, Linked to User)
  - **Audio** — leave as "Not Collected" because transcription is on-device and never leaves the phone. If asked: "Audio is processed exclusively on-device via SFSpeechRecognizer with requiresOnDeviceRecognition=true. No audio is transmitted or stored."
  - **Product Interaction** (Analytics, Linked to User) — PostHog events.
  - **Crash Data** (Analytics, Not Linked) — Sentry.
  - **Coarse Location**: Not collected (we don't).

### 7d. Age rating
- 17+ (realistic scam content in demo scenarios + Recovery Concierge content).

### 7e. Privacy policy URL + Support URL
- Both must be live before submission. Use the templates in `~/aegisdial-backend/legal/`:
  - https://aegisdial.com/privacy
  - https://aegisdial.com/support (or your email)

## 9. Archive + upload

In Xcode:
1. Select **Any iOS Device** (not simulator) as build destination
2. Product → Archive
3. Organizer opens → **Distribute App → App Store Connect → Upload**
4. Xcode signs + uploads. ~5–10 min.
5. Refresh App Store Connect → TestFlight tab. Your build should appear in "Processing" (10–30 min) then "Ready to Test."

## 10. Internal testing

- TestFlight → Internal Testing → Create Group "AegisDial internal"
- Add your own email as a tester (needs to be on the Developer Program).
- Once build is Ready: install TestFlight on your phone, sign in with the same Apple ID, accept invite, install build.

Smoke test on real device:
- Sign up flow
- Paywall (use a sandbox Apple ID created in App Store Connect → Users → Sandbox Testers)
- **Shield this call** button → grant mic + speech permission → say "move your money to a safe account right now" → see risk escalate
- **Try a demo call** in Settings → play "bank fraud department" → see the same UI live
- Add a family contact with a safe word
- Add your email as a breach monitor → see the LinkedIn mock exposure
- Accept notification permission at end of tour → verify `/v1/device/register` hits in Fly logs

## If the first archive fails

Most common: **entitlements mismatch**. In Xcode, the error will say which entitlement isn't provisioned. Usually means either (a) the App ID on developer.apple.com doesn't have that capability enabled, or (b) the provisioning profile is stale. Fix on developer.apple.com side, then Xcode → Product → Clean Build Folder → re-archive.
